## 现在的主因：`connect:occupied`（9 次）—— 这是真实的几何限制

看代码（`connect.mjs:960-968`）：

```js
if (blockedBy) {
    return failure({
        code: "occupied", field: "to",
        message: `所有候选路径都被挡住；第一处冲突在 ${blockedBy.x},${blockedBy.y}（${blockedBy.what}...）`,
        hint: "这是「撞了」，不是参数错。要绕开需要阶段 3 的布线；机器永远不会被覆盖。",
        ...
```

**宏的设计是不覆盖机器。** 所以「M1 → C1」这条模型反复尝试的连接，
在这个世界里可能**几何上就走不通**（中间隔着别的机器）。

这不是 prompt 能修的，也不是宏的 bug —— 是**布线能力不足**。
`hint` 自己说了：「要绕开需要阶段 3 的布线」。

## 这意味着什么

### 1. 之前所有「文本层」的结论都要打折

- `AB-PROMPT-RESULT.md` 的 16/23（p=4.95e-07）→ 执行层 2/23
- `EXPERIENCE-AB-RESULT.md` 的 8/15、10/15 → 执行层 1/8、2/10
- 本轮的 13%/20% → 执行层 0/15、1/15

**每一层看都「有效果」，到了执行层全部归零。**

⇒ **「模型说了什么」和「世界变了什么」之间的漏斗损失是 96%。**
在这个漏斗修好之前，任何 prompt 层的优化都测不出来。

### 2. 用户说的「低质量」有一部分来自这里

用户的原话：「建的很丑陋也没有调理的绕远路，明明有可以快捷提高产能的方法却没有用」。

现在有了一个更具体的解释：

> **模型不是不想做，是它想做的大多做不到。**
> 它写出来的 58 个计划里，54 个被宏拒绝。

它被拒绝之后，要么重试（消耗预算），要么换个更保守的动作（可能更差）。

### 3. `QUALITY-METRICS.md` 的判据门槛设错了

那份文档说「L1+L2 已经能做到。本轮的分野在 L3+L4」。

**实测：L1/L2 远没有做到。** 执行率 4% 意味着大部分轮次根本没改世界。

⇒ 判据顺序必须反过来：**先把「意图 → 可执行」当成第一指标**，
它上去了再看 L3/L4 才有意义。

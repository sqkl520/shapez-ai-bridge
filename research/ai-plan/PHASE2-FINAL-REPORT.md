### 2. 「没人算坐标」这条设计被真正落实

不是靠嘱咐 LLM「别算坐标」，而是**结构上让它看不到坐标系**：

- prompt 里只有句柄（`B7`、`C1`）与拓扑描述（`上游=B2 下游=C3 货=0`）
- 坐标只能通过三种算子引入：`$ref` / `$uids` / `$bbox_of`
- 每个坐标都带 provenance 标签（`obs:uid=N` / `macro:token` / `computed:bbox_of[...]`）
- 变异测试证明：改一个坐标，provenance 立刻红（这条防线曾经是空的，本轮修掉）

### 3. 真实数据验证了「宏层可行」

## 三、为什么没成功（本轮最有价值的产出）

### 决定性发现：模型的误选是**合理的**

```
模型常选的 hub 环 B135/B136/B137  → 真能走到 hub：3/3
正解三条       B81/B82/B69        → 真能走到 hub：0/3
```

模型的推理链：
1. goal 要 `RuRu----`，hub 的 `delivered = 0`
2. 所以要切割
3. 哪条带子在往 hub 送货？→ hub 环上那三条
4. 把这三条改成切割机

**在它掌握的信息下，这是最合理的推理。** 它甚至选对了"真正连通 hub"的那三条。

错的是我们的前提：**L4 的正解要改造的那三条带子，本身并不通往 hub。**
它们是上游原料链，改造后才产生 `RuRu----` 并接进 balancer → hub。

**模型需要的不是"哪条离 hub 近"，而是"哪条链在造什么形状、goal 要什么形状"。**
这个信息 prompt 里完全没有。

### 5 次尝试的完整失败分布

| # | 选择 | 结果 | 性质 |
|---|---|---|---|
| 1 | hub 环 B135/B136/B137 → cutter+trash | `out_of_scope` | 位置错 |
| 2 | hub 环三条 → rotater | `ambiguous_site` | 位置错 |
| 3 | C1 的输出带 B84/B85 → rotater | `precondition_failed` | 位置错 |
| 4 | hub 环 B135 → cutter | `ambiguous_site` | 位置错 |
| 5 | M3 链（含正解）→ belt 模式 | plan ok | **选中 3/3，但 region 过大** |

## 六、诚实边界

- **5 次样本太小**，「0/5」的置信区间很宽，不能断言"永远做不到"。
- 实验只走到 **plan 阶段**。即使 plan 全对，**也不等于产线会通**。
- 离线验不了 L3/L4/tx（`offline_boundary.mjs` 有 25 条测试守着）。
- 所有结论基于 `virtual/opus` 一个模型（经代理）。换模型可能不同。
- **从未在真实游戏里跑过**——桥接不在线，`success` 分支是未验证的代码。

## 七、第三轮（本报告写完后补充）

修完第二轮验收指出的三处后重跑真 LLM 5 次，结果显著改善：

| 指标 | 第二轮 | 第三轮 |
|---|---|---|
| 看到正解 | 5/5 | 5/5 |
| **选中 ≥2 条** | 1/5 | **4/5** |
| **选中全部 3 条** | 1/5 | **2/5** |
| 精确匹配 | 0/5 | 0/5 |

**模型的推理发生了质变**：从「盯着 hub 入口猜」变成「正确指向 M3 矿机链」。
这直接证明了「给对信息就能改善」这个判断——不是模型不行，是之前没给够。

**瓶颈转移了**：现在卡在**算子表达力**，不在选择。
`$bbox_of` 给最小外接矩形，而 `replace_run` 要恰好那几格；
链拐弯或并行时，矩形会框进不该动的东西（`occupied` / `not_a_run` / `precondition_failed`）。

最接近成功的一次（#5）：**选中 3/3，给了正确的 `[cutter, trash(left)]`，只差 region 太大。**

## 九、一句话总结

**系统建成了，设计的核心主张（LLM 不算坐标）被证实可行；核心赌注尚未达成，但每轮实验都在把失败原因往前推一格：**

> 第 1 轮：LLM 看不到目标（信息量问题）
> 第 2 轮：看到了但选不中（模型选的位置是"合理的"——它选了真能到 hub 的那三条）
> 第 3 轮：**选对了 4/5，卡在怎么表达要改的那几格（算子表达力问题）**

每一步都是具体的、可修的工程问题，没有一个是方向性错误。

| 轮次 | 主要失败原因 | 性质 |
|---|---|---|
| 1 | 看不到目标（163 条里选 12 条） | 信息量 |
| 2 | 选 hub 入口（"货没进来改入口"） | 信息量（缺矿图） |
| 3 | 选对了链，但 region 表达不了 | 算子表达力 |
| 4 | 不知道怎么造（要 rotater 吗） | 形状代数 |

**每一轮修完，下一层问题就露出来。问题在向更难、也更有价值的方向移动。**

而第四轮暴露的那个缺口最值得注意：**形状代数已经在仓库里了**
（`research/ai-player/proto/shape-ops.mjs` 的 `cutHalf`，`compile.mjs:568` 早就在用），
只是从来没接进 prompt。所以下一步不是「造新能力」，而是「把已有能力接上」。

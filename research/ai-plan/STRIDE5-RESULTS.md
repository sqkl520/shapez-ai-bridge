# stride=5 / SZBP1 v2 的实测结论（主线程，2026-10-24）

> 结论先行：**v2 的平行数组 `o` 已实现并入库，它守护的是"声明邻居拓扑"下的拐角稳定性；
> 它不能防住"事后在拐角旁乱贴一格"** —— 后者属于纪律（C2：整块贴完不旁补），不是格式能解决的。
> 这一点与 P7-F2 的原始报告**不矛盾**，而是把它的适用边界量清楚了。

## 2. 三个关键实测（决定了 `o` 该怎么填）

### 2.1 `orig` 不能简单写成 `rot`
`computeBelt(orig, 邻居)` 是游戏的事后重算模型。要让拐角停在 `(rot, rv)`，必须解不动点：
```
对每个带子格：找 orig ∈ {0,90,180,270} 使 computeBelt(orig, 声明邻居) === (rot, rv)
有解 → 写进 o；无解 → 该格在受扰时必翻 → **整单拒绝**（不产会翻的蓝图）
```
编译器（`emit.mjs`）现在就是这么做的。**反解验证**：真实工厂里 23 个"左邻朝右喷"的拐角，其 `orig` 全是 180（不是 rot），与该模型精确吻合。

### 2.2 邻居编码：上游是 ejector，下游是 **acceptor**
```
ns = [ { toDirection: inDir },            // 上游把货喷进本格（喷口朝本格）
       { fromDirection: OPP[outDir] } ]   // 下游接货（槽面朝本格）
```
⚠️ 把下游写成 `toDirection` 会让**所有**拐角判无解（我曾踩，L1 门 85→58 立刻暴露）。

### 2.3 ★ 边界：`o` 只守护"声明过的邻居"
| 场景 | orig=0 的稳态 |
|---|---|
| P7-F2 的 3 格粘贴（**下游缺失**） | 🔴 翻成直带 |
| P7-F2 + 左侧 ejector | 🔴 翻 |
| **编译器产物（下游 acceptor 在）** | ✅ **稳** |

P7 的实验粘的是"只有上游、没有下游"的孤立拐角 —— **编译器从不产出这种形状**（每个 outDir 都有下游）。
在完整链上步进 60 tick，拐角 `r0/rv2` 保持不变（`results/v2-orig-compiler.json`：0/1 翻）。

⇒ 因此：
- **v2 对编译器自身产物是有效的**（它保证 `(orig, 声明邻居)` 是不动点）；
- **对"用户/其他 agent 事后在拐角旁乱贴"仍无能为力**（那是新邻居，任何 orig 都不保证）——
  这条是 `compiler-constraints.md` C2"整块贴完不旁补"的纪律，无法靠格式解决。

## 3. 容量与版本兼容（P6 实测，已复述进 PROTOCOL）

- 平行数组比 stride=5 贵 ~5pp（2000 格：4950 vs 4707 字符），但**旧解码器原样可读**；
- 改 stride=5 若忘升版本号，`n%4==0` 时旧解码器会**静默**读出错位实体（n=4/8/12/16 中招）并盖进世界；
- v2 文本被 v1 解码器读：`o` 被忽略、`e` 正常（8 格仍是 8 格，实测断言锁定）。

## 4. 未做 / 边界

- 编译器产物的 `orig` 当前恒等于 `rot`（因为布局本身就让它是不动点）——`o` 字段的价值在**未来增量扩建**时才显现，现在写入是为那时留好信息。
- 尚无"多分支 + 多级 stacker"的 `o` 验证（那类目标仍被 painter→hub 车道/B-3 挡着）。
- 真实工厂 23 个样本中 `orig≠rot` 是**玩家手放**的产物；编译器不需要模仿它，只需保证自己的不动点成立。

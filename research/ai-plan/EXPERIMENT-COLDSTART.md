## 3. 失败模式分类（这是本次实验最有价值的部分）

### 3.1 模型**从不删东西**（5/5）

五次尝试，**没有一次**想到要 `remove_run` 或 `replace_run` 删掉那三条带子。
它一致地选择 `insert_machine`——"在某个位置插一台机器"。

**为什么**：模型把 L4 理解成"加一台切割机"，而不是"把这段带子改造成切割机"。
从 `obs` 看，`(4,-13)` 已经有一条带子；模型倾向于**在旁边加**，而不是**就地改**。

**这是提示词的问题**：prompt 里没有一句话说明"改造既有带子"是允许且常见的。
`replace_run` 在候选宏里，但模型没有理由优先选它。

### 3.2 模型选的位置有系统性偏差（4/5）

| # | 选的位置 | 与正解的距离 |
|---|---|---|
| 2 | B84 | 不是目标三条 |
| 3 | B85 | 不是目标三条 |
| 4 | B112 | 是目标的上游（M3 矿机链） |
| 5 | B135 | hub 入口那一圈 |

**#4 最接近**：它选了 M3 矿机链的头部（B112），说明它**理解了"要从矿机那头改"**，
但选的是链头而不是中段的目标位置。

**#5 的推理是错的但可理解**：它说"hub 已经有供料带但没交货，所以问题在入口"——
从 `obs` 看，hub 环上确实有 3 条带子（B135/B136/B137），且 delivered=0。
它推断"货到了 hub 却没进来"，所以想改入口。**实际原因是那三条带子不在通往 hub 的路径上。**

### 3.3 机器名拼错（1/5）

`"machine":"rotator"` —— 正确是 `"rotater"`。宏正确地拒绝了（`unsupported_building`）。
**这类错误 prompt 完全可以防**：宏卡片里应该列出合法的 machine 值。

### 3.4 `LLM_NARRATION` 造成真实损失（1/5）

第 5 次 `say` 写了 349 字符（上限 280），整轮被拒。
但它的动作 `insert_machine(at=B135, cutter)` 是**结构合法**的——
被拒的理由纯粹是叙述太长。

这是 C agent 在实现时质疑过、红队也批评过的那条规则：
> 「拿正确性给格式买单」

**实测证实了这个批评**。`LLM_NARRATION` 应该降级为警告，不该整轮作废。

## 4. 对照实验：当 LLM 选对时，链路是通的

用 `test/fixtures/llm/l4-coldstart-oracle`（**人写的、知道正解**的夹具）跑：

```
看到 3/3 · 选中 3/3 · plan ok · 删除集合精确匹配 · 放置坐标正确
```

**这证明了两件事**：
1. 下游链路（parse → coords → 宏 → planToTxOps）**没有 bug**。
2. 失败的**唯一**原因是 LLM 没有选对，而不是系统不会执行。

⚠️ **这个对照不是"实验通过"**——它是人先看了答案写出来的，信息量仅限"链路没坏"。

## 6. 核心赌注的裁决

> 「宏动作层能把真实存档从 0 抬起来」

**结论：仍未证实，且当前实现达不到。**

但这次的「未达成」有明确的、可行动的诊断：

| 失败点 | 性质 | 可修性 |
|---|---|---|
| 模型只用 insert_machine、从不删 | **prompt 引导缺失** | 高——加一句"改造既有带子是常见的" |
| 机器名拼错（rotator） | **prompt 信息缺失** | 高——宏卡片列合法值 |
| `LLM_NARRATION` 整轮拒 | **规则过严** | 高——降级为警告 |
| 选中 hub 入口而非目标区 | **缺形状/拓扑线索** | 中——需要在 prompt 里标注"哪条链在造什么" |

**这些都不是"宏动作层"这个方向的问题**——它们全在 LLM 层与 prompt 层。
宏层（`replace_run` 能一条调用解出正解）已经被对照组证明是通的。

## 7. 建议的下一步（按性价比排序）

1. **修 `LLM_NARRATION`**（5 分钟）：降级为 `warn`，不整轮拒。
   实测已经损失了 1/5 的有效尝试。

2. **在 prompt 里加"改造"引导**（30 分钟）：明确说明
   「既有带子可以被 replace_run 就地改造成机器；不必在旁边新建」。
   这是 5/5 次失败的直接原因。

3. **宏卡片列出合法 machine 值**（10 分钟）：防 `rotator` 这类拼错。

4. **在 prompt 的 BELTS 段标注每条链的产出**（半天）：
   目前只写「上游/下游/货量」，没写「这条链在造什么形状」。
   #4/#5 的误判正是因为模型不知道哪条链与 goal 相关。

5. **重跑本实验**，看 1-4 后能否从 0/5 提升到 ≥3/5。
   **这是唯一能证实或证伪核心赌注的方法。**

---

## 8. 诚实边界

- 本实验只走到 **plan 阶段**，没有写世界。即使 plan 全对，
  也**不等于**产线会通（`offline_boundary.mjs` 已说明：离线验不了 L3/L4/tx）。
- 5 次样本量很小。要做到「连续 5 次 ≥3 次成功」的原始判据，
  需要在修完 1-3 之后重跑，且可能要 10 次以上才有统计意义。
- 真 LLM 每次约 30–40 秒（该代理的模型会先生成很长的 thinking），
  5 次实验约 4 分钟。成本可接受，可以多跑。

# prompt 补全观察面 —— A/B 实验结果（负结果）

> 2026-11-02。**这是一个负结果，必须如实记录。**

---

## 结论

**「补全观察面」的改动，在这个场景上没有带来决策改善，反而可能有害。**

| 臂 | 配置 | k/n | 命中率 | 95% CI |
|---|---|---|---|---|
| **A** | **改前（旧 sys + 旧 user + 无 production）** | **9/10** | **90%** | 60–98% |
| A2 | 只把 B16 换成 B34（诊断点名的那个） | 9/10 | 90% | 60–98% |
| F | 全量新，但删掉规则 10 的 EXCEPTION 段 | 16/20 | 80% | 58–92% |
| B | 全量新（sys + B34 可见 + production + CAPACITY） | 14/20 | 70% | 48–85% |
| D | 旧 sys + B34 可见 + production 一行 | 6/10 | 60% | 31–83% |
| E | 新 sys + B34 可见 + 无 production | 5/10 | 50% | 24–76% |
| C | 新 sys + B34 可见 + production 一行 | 4/10 | 40% | 17–69% |

「命中」= 模型给出的计划是 `connect(B34 → H1)`（补那 3 格带子的正解）。

---

## 关键发现

### 1. 改前本来就够用：B34 不在带子表里，模型照样能找到

```
改前 prompt 里 B34 可见? false
表头: (12 of 34; 1 referenced by diagnosis)
```

**但 A 臂 9/10 选中了 `connect(B34→H1)`。**

诊断里写了 `handles B34`，这就够了 —— 模型不需要在 BELTS 段里看到它的详细描述。
**我修的「句柄可见性」对这个场景不是必需的。**

`A vs A2` 的对照最干净：两者都 9/10，`p = 1.0000`。
差别只是把带子表里的 B16 换成 B34 —— **零影响**。

### 2. 给模型更多信息，反而让它做了更差的选择

B/C/D/E 臂（都有 B34 可见）出现了一种 A 臂没有的行为：

> `"Route the cutter's kept-half belt into the hub and **cap the dead-end belt with a trash can**."`
>
> `"B34's outlet dead-ends with 30 cargo piled up, **jamming the line**"`

**模型把 B34 当成了「该扔掉的死端」，而不是「要接到 hub 的那一段」。**

而 A 臂（看不见 B34 的细节）直接照着诊断的 `handles B34` 去做 `connect` —— 做对了。

**这是个真实的反效果：补充上下文让模型有了一个错误的解释空间。**

### 3. 唯一有统计意义的差异：C 最差

`C 4/10 vs F 16/20, p = 0.0449` —— 唯一 p < 0.05 的对照。

C 的配置是「新 sys + B34 可见 + production 一行」，
F 是「C 去掉规则 10 的 EXCEPTION 段」。

⇒ **规则 10 的 EXCEPTION 段（“若诊断说 fits at 0 place(s) 则……”）是有害的**，
它让模型倾向于放弃 `connect`，转而去 `trash_unused`。

### 4. 统计上，大部分差异都不显著

| 对照 | p |
|---|---|
| A(9/10) vs B(14/20) | 0.3717 |
| A(9/10) vs F(16/20) | 0.6400 |
| A(9/10) vs C(4/10) | 0.0573（接近但不显著） |
| B vs F | 0.7164 |
| E vs C（只差 production） | 1.0000 |
| D vs C（只差 system） | 0.6563 |

**除了 C vs F，没有任何一条达到 p < 0.05。**

n=10~20 的置信区间很宽（A 的 95% CI 是 60–98%），
所以「A 是 90%、B 是 70%」这个差距**不能断言是真的差异**。

## 这意味着什么

### 我做错的地方

1. **假设「模型看不见 B34 所以找不到」——这是错的。**
   实测证明诊断里的 `handles B34` 已经足够。

2. **改了 4 处，一次只测一个场景，没有先做单因素实验。**
   如果先做 `A vs A2`（只改 B34 可见性），5 分钟就能发现这条没用。

3. **没预料到「补充上下文会引入错误解释」。**
   给模型看「B34 上游=B30 下游=无 货=0」之后，它把「下游=无」理解成「该扔掉」，
   而不是「该接上」。

### 哪些改动仍然可能有用（但未证实）

- **`production` 接入**：`E vs C` 的 p=1.0，这个场景里没有体现。
  但它的价值在于「让模型知道改之前后产量变没变」—— 这在**多轮**场景才显现，
  单轮 A/B 测不出来。
- **`CAPACITY` 段**：B 臂（有 CAPACITY）70%，C 臂（无）40%，但 p=0.1391 不显著。
  而且 B 的 20 次里含了不同批次，不能直接比。
- **规则编号重排**：`D vs C` 只差 system，p=0.6563，无影响。

**结论：在这个「修断点」场景上，四处改动都没有证据表明有用，其中 EXCEPTION 段有害。**

## 必须做的下一步

### 1. 换场景

这个场景（断点）**太简单** —— 改前的 prompt 就能 9/10 做对。
真正的差异应该出现在**产能场景**（利用率 28%、瓶颈 cutter、有升级可选）。

在那种场景下，`CAPACITY` 段才是唯一的信息来源 —— 旧 prompt 完全没有这个概念。

### 2. 单个变量地测

不要一次改四处再 A/B。正确做法：
- 先 `A vs A2`（只改 B34 可见）→ 已做，零影响
- 再 `A2 vs A2+production`（只加 production）
- 再 `+CAPACITY`（只加产能段）
- 最后 `+sys 重排`

每一步都能归因。

### 3. 如果异常场景也证明无用，就回退

**不要因为「改了这么多」就保留。** 数据说没用就回退。

## 诚实边界

- **只测了一个场景**（半成品世界的断点修复）。不能外推到产能 / 布局 / 冷启动场景。
- **n=10~20**，置信区间宽（±15-30 个百分点）。
- **模型有随机性**：同一条 prompt 输出 1000–8000 tokens 不等，`say` 措辞差异很大。
- **「命中」这个判据本身有争议**：`connect(B34→H1)` 是正解，但
  `connect(C1→H1)`（从 cutter 右槽直接接）在物理上也可能成立 ——
  只是会覆盖那段已有的带子。我没把后者算作命中，但它不一定是错的。

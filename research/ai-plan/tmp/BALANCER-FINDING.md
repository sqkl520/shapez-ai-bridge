# balancer 是我一直缺的工具（2026-10-26）

## 发现

用户 level-11 存档里 **514 个 `code 4`** —— 我一开始以为是带子变体，查了
`buildings/balancer.js:37` 才明白：

| code | 是什么 | 尺寸 | 作用 |
|---|---|---|---|
| **4** | balancer（默认变体） | **2×1** | 2 进 2 出，自动均衡 |
| 5 / 6 | merger | 1×1 | 2 进 1 出（合并） |
| 47 / 48 | splitter | 1×1 | 1 进 2 出（分流） |

514 个 balancer = 我工厂里完全没有的**组网能力**。

## 为什么它重要

balancer 默认变体的槽位（`balancer.js:178-196`）：

```
输入：local (0,0) ← bottom    输出：local (0,0) → top
      local (1,0) ← bottom          local (1,0) → top
```

两个输入都在南面、两个输出都在北面，**逐格对齐**。游戏内部会自动均衡——
哪边堵了就往另一边分流，哪边空了就从另一边取。

这意味着：

- **一条带子喂多台机器**不需要手工设计分流比例，放一个 balancer 就行
- **多台矿机并一条带子**同理
- 它可以**串联**：balancer 串 balancer 形成分配树

## 我的编译器缺什么

看 `op-templates.mjs`，机器模板只有 `mine / cut / rotate / stack / mix / paint / trash`。
**balancer 根本没有模板**，所以编译器永远不会产出它。

而真人用 514 个。这不是"优化项"，是**基础器件缺失**。

## 这解释了我反复失败的那个实验

我手工搭 3 台矿机并联，试了三次都错：共享主干只接通最上面那台、hub 入口互相覆盖、
带子压到 hub 上。如果当时用 balancer：

```
矿机 → 带 → balancer ← 带 ← 矿机          （2 台合并）
                ↓
             带 → hub
```

一个器件解决，不用算入口分配。

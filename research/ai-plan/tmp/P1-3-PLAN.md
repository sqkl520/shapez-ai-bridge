# P1-3 修复方案：矿机落点逐台独立

## 问题

`CgScScCg` 在**全部四个种子**上失败（43391 / 60908 / 77844 / 15935），原因固定为
`no-resource-in-range`。真实通过率是 **21/28**，不是文档里沿用的 "7/7"。

根因在 `jointResourceShift`（`place.mjs:1330`）：它返回**单一平移量 `[dx,dy]`**，
把整簇矿机一起搬。所以矿机的相对偏移完全由 DAG 布局硬定：

```
CgScScCg: n0@rel(0,0) -b------@rel(-8,0) -g------@rel(-4,0) n6@rel(4,0) ---g----@rel(-12,0)
```

五台矿机必须恰好落在一条 5 格等距直线上、且各自压到正确的矿。真实矿图的矿簇随机散布，
这个关系几乎不可能成立。扩大 `--range` 到 256 结论不变——不是搜索不够，是约束本身错了。

## 方案：改为逐台独立落位

### 核心改动

`jointResourceShift` 从"返回一个平移量"改为"返回逐节点坐标"，并允许矿机**各自选行**：

1. **锚定第一台矿机**（保持既有行为，确定性不变），得到基准 `anchorCell`。
2. **其余每台矿机独立**在区域里找**最近**的该类资源格，约束：
   - 不压在 hub 的 4×4 上
   - 不与已选格重复
   - 不与其他矿机同列（保留 `pickResourceCells` 已有的"不同列"纪律，
     避免两条竖直通道重叠——这是 M4-SUCCESS 的前置条件）
3. 返回 `{ok:true, cells: Map<nodeId, [x,y]>}`（世界系），**不再有统一 shift**。

`place()` 里把原来的
```js
const [dx, dy] = js.shift;
for (const n of nodes) { n.x += dx; n.y += dy; n.row += dy; }
```
换成**逐节点**落位：矿机节点按 `cells` 设 x/y，非矿机节点跟随锚定矿机的平移量
（保持下游相对位置不变，只让矿机自己散开）。

### 为什么这样能成

矿机的唯一硬约束是"压在自己的资源上"（`systems/miner.js:48-56` 读的是
`staticComp.origin` 的下层内容）。相对间距**完全自由**——通道本来就该处理
"上游在任意位置"的情况，`planChannel` 已经支持任意两端点。

### 回落策略（关键：不能让能跑的种子退化）

逐台独立可能产生一条**超长或交叉**的通道，导致下游路由失败——而原来的刚性方案在
某些种子上**恰好能成**（`CrCrCrCr` 在 43391/77844/15935 都成功）。

所以做成**两段式**：

1. 先按**逐台独立**排；编译走完整流程。
2. 若下游失败，**回落到原来的刚性 `jointResourceShift`**（保留旧函数）。

这样：
- 能跑的种子：独立方案成功就用独立方案；失败则回落，结果不差于今天。
- 跑不了的种子（`CgScScCg`）：只有独立方案有机会成功。

**但"先试后回落"会让输出依赖下游结果，可能破坏确定性测试。** 所以顺序反过来更稳：

1. **先试刚性**（完全等于今天的行为，逐字节不变）。
2. 刚性失败时，**才**用逐台独立重试。

这样所有当前能编译的目标**输出逐字节不变**（刚性先成功），只有当前失败的目标
才走新路径。零回归风险。

### 需要同步改的测试

`placer/test.mjs:1005` 现在断言：
```js
eq(new Set(ys).size, 1, "⑥-a 同色/跨色都在同一行（planMinerColumns 只解「同一行」这一档）");
```

这条断言把"只能同一行"固化成了正确性。修复后它应当改为**在能同行的场景仍同行**
（43391 上有这种场景），另外新增一条**独立落位**的用例证明可以不同行。

`planMinerColumns` 本身（行内 x 规划）保留不动——它仍然是第一段的选择器。

### 完成判据

1. `CgScScCg` 至少在**一个**种子上 `ok:true`
2. 其余 6 个目标的编译结果**逐字节不变**（对 4 个种子逐一比对 entities 数量与坐标）
3. placer 全套仍绿
4. 全家族回归仍绿

### 风险

- **长通道**：矿机散开后通道可能变长，穿越机器导致 `cell-occupied`。这是**诚实的失败**，
  不是 bug——但要在 hint 里说清楚是"独立落位导致的通道不可达"，而不是笼统的失败。
- **隧道机会**：散开后的长通道正好是隧道的用武之地。这是 P1-3 与隧道能力的交汇点，
  也是先做 P1-3 的理由。

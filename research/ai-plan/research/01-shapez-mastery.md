## 1. TL;DR（10 条，直接可执行）

1. **一条满带 = 5 台矿机**（0.4 vs 2.0/s），不是 1 台；矿机要**铺满整个矿簇**，不是挑一格。
2. **升级倍率是加法不是乘法**：1 → 1.5 → 2 → 3 → 4 → 6 → 7 → 8，所以「带速 : 矿速」永远是 5 : 1，**四条升级线必须同档**，否则配比立刻变成 6.7~7.5 台矿机/带。
3. **先升瓶颈段，不先升带子**：矿机是瓶颈时升带子对产量 **零贡献**；第一个真正加产的是 miner T1。
4. **别在 hub 旁边建厂**：官方两次警告 + 社区建议留 **16 格缓冲**，否则后期 16 路进料/分流没地方放。
5. **hub 有 16 个独立进料槽（12 个格子，4 个角格双向）**，每个槽能吃满一条带；把多条线并成一条再进 hub，等于把 4 条带砍成 1 条。
6. **每个机器输出都必须有去处**：切割机有两个半成品出口，只用一个另一个必须接垃圾站，否则机器 2 个 charge 后就停摆。
7. **染色在切割之前**：上色器染的是「整个形状的所有象限」；先切后染，形状数 ×2（半切）或 ×4（四切），上色器就要 ×2~×4。
8. **旧产线永不拆**：升级商店按「累计形状」扣库存，T1~T5 会反复要同一种形状；拆了就得重建。
9. **MAM 是 20 关以后的东西**：wires 在 L20、filter 在 L21、analyzer/虚拟处理器在 L25；在此之前「专用线 + 可复制模块」才是正解。
10. **验收标准是「实测吞吐 ≥ 带的 80%」**，不是「关卡过了」；用 `production` 读 delivered 速率，而不是看 hub 库存涨了。

### 2.2 配比推导（喂满一条满带要几台）

设当前同档倍率为 `m`（T0 时 m=1）。带速 `B = 2m`。

| 机器 | 单机吞吐（同档） | 喂满 1 条带需要 | 备注 |
|---|---|---|---|
| 矿机 | 0.4m | **5** | 官方 tip 直接给出 |
| 切割机（半切） | 0.5m 输入 | **4** | 输出是 **2 条带**（左右半各 2m） |
| 四切机 | 0.5m 输入 | **4** | 输出是 **4 条带**（四个角各 2m） |
| 旋转机 | 2.0m | **1** | 永远不是瓶颈，可串在任意位置 |
| 混色器 | 0.4m（2 进 1 出） | **5** | 按「染料条」计 |
| 上色器 | 0.333m（1 形状 + 1 染料） | **6** | 染料消耗 0.333m/s |
| 双联上色器 | 0.5m 形状/s（每 charge 吃 2 形状 + 1 染料，出 2 形状，**进出等量**） | **4** | 4 台正好吃满 1 条输入带、也正好吐满 1 条输出带；染料只要 0.25m/s（普通上色器的一半） |
| 四色上色器 | 1.0m | **2** | 一次可上 4 种颜色，MAM 用 |
| 堆叠机 | 0.25m 输出（0.5m 输入） | **8** | 两条输入带各需 4 台堆叠机对接 |
| 平衡器 | 内部 4 charge/s × 2 物品 = **8m 物品/s**（端口上限才是带速） | 1 台管 **2 条带** | 2×1 占地；内部比带子快一倍，永远不是瓶颈 |
| 分流器 / 合流器 | 分流 1→2、合流 2→1（都只做「拆/并」，不做缓冲） | 1 台管 **1 条带**（分流后每条 1m，合流后仍 1 条） | 1×1 占地；不是瓶颈 |

**关键推论（很多人会算错的一条）**：
- 半切机「4 台/带」指的是**输入**；4 台切完，输出半成品总量翻倍 = **2 条带**。所以一条整形状带 → 4 台切割机 → 两条半形状带 → 后续要么两路并行，要么用堆叠机/合流器再并回去（并回去会回到 1 条带，产能减半）。
- 四切机同理：1 条整形状带 → 4 台四切机 → **4 条角块带**（每种角一条满带）。这是 MAM 供料模块的基本比例。
- 双联上色器常被误算成「8~9 台/带」。按源码 `2 × 1 × 1/8 = 0.25 charge/s`，每 charge 吃 2 个、出 2 个，实际是 **0.5 形状/s ⇒ 4 台/带**；它比普通上色器快 1.5 倍、染料只要一半。`[官方源码]`（本仓库 `tmp/STRATEGY-RESEARCH.md` 里写的 8~9 台是错的，本次以源码纠正）
- **链式矿机（L11 解锁）不加速**：`systems/miner.js` 里每台矿机各按 `getMinerBaseSpeed()` 独立开采，chainable 只是把物品「转交给正前方那台」（6 格缓冲），总量与各接各带完全相同。它的价值是**空间**（可以肩并肩密排，只有最后一台接带）。`[官方源码]`

### 2.3 升级倍率：**加法**，不是乘法

这是本次调研最重要的一条纠正。升级链 `regular.js:66,75` + `hub_goals.js`：

```js
const fixedImprovements = [0.5, 0.5, 1, 1, 2, 1, 1];   // 每一档的 improvement
// 购买时：
this.upgradeImprovements[id] += tierData.improvement;   // 从 1 开始累加
// 速度：
getBeltBaseSpeed()  = 2 * upgradeImprovements.belt
getMinerBaseSpeed() = 0.4 * upgradeImprovements.miner
```

所以倍率序列是 **1, 1.5, 2, 3, 4, 6, 7, 8**（第 8 档之后进入无限档，每档 +0.1 / +0.05 / +0.025 / +0.0125）。

| 档位 | 倍率 | 带速 | 矿速 | 矿机/带 |
|---|---|---|---|---|
| T0（未买） | 1.00 | 2.0 /s | 0.40 /s | 5.00 |
| T1 | 1.50 | 3.0 /s | 0.60 /s | 5.00 |
| T2 | 2.00 | 4.0 /s | 0.80 /s | 5.00 |
| T3 | 3.00 | 6.0 /s | 1.20 /s | 5.00 |
| T4 | 4.00 | 8.0 /s | 1.60 /s | 5.00 |
| T5 | 6.00 | 12.0 /s | 2.40 /s | 5.00 |

### 2.4 一个矿簇能喂几条带

矿点由地图分块程序生成（`map_chunk.js` `_generatePatches` / `_internalGeneratePatc`）：

- 每个 chunk 16×16；矿簇大小 `size = max(2, round(1 + clamp(distanceChunks/8, 0, 4)))`，即 8 chunk 内 size=2，16 chunk 左右 size=3，24 → 4，32+ → 5。
- 簇是若干半径递增的圆叠出来的「锯齿圆盘」。**实际格数**：我按源码的生成算法（`_internalGeneratePatc` 的循环、`nextRange(0.9,1.1)` 抖动、去重）做了 500 次蒙特卡洛模拟，结果如下。仓库里另一份笔记估 size2 为 25~30 格，与模拟的 11~29 有出入，**所以下表按区间理解，不要当精确值**。

| size | 模拟最少格 | 模拟中位格 | 模拟最多格 | 满铺矿机产能（T0） | 可喂满带数（T0） |
|---|---|---|---|---|---|
| 2 | 11 | **~20** | 29 | 4.4~11.6 /s | **2~6 条（中位 ~4）** |
| 3 | 25 | **~47** | 66 | 10~26 /s | 5~13 条（中位 ~9） |
| 4 | 55 | **~80** | 112 | 22~45 /s | 11~22 条（中位 ~16） |
| 5 | 79 | **~117** | 155 | 32~62 /s | 16~31 条（中位 ~23） |

因为矿机和带子按同一个 `m` 缩放，**「一个矿簇能喂几条带」与升级档无关**：`格数 × 0.4m / 2m = 格数 / 5`。

> 这条直接解释了我们 AI 的错误：开局矿（size 2，约 20 格）理论能喂 4 条带，AI 只放了 1 台矿机 → 只用了 **1/20** 的矿点产能。

**开局固定矿点**（`_generatePredefined`，`[官方源码]`）：

| 资源 | 区块 | 世界坐标 | 说明 |
|---|---|---|---|
| 红染料 | (0,0) | (7,7) | 固定 7×7 位置 |
| 圆 `CuCuCuCu` | (-1,0) | **(-9,7)** | 固定 |
| 矩形 `RuRuRuRu` | (0,-1) | **(5,-7)** | 固定 |
| 绿染料 | (-1,-1) | 区块内随机 | 固定存在 |
| 星 `SuSuSuSu` | (5,-2) | **(85,-23)** | 固定，87 格外 |
| 风车 `Cw` | — | **无固定点** | 只在 ≥7 chunk 的随机形状簇出现 |

`[官方源码]` 形状簇生成权重：`rect 100 / circle 50+2r / star 20+r / windmill 6+r/2`，且 `r < 7` 时 **star 与 windmill 权重归零**；`r < 10` 全是四角同形状，`r ≥ 15` 才出现四角随机的复杂形状。颜色簇 `≤2 chunk` 只有红/绿，**蓝染料必须 >2 chunk**。

### 2.5 Hub 的真实吞吐

- 16 个槽，每槽只受来料带速限制：T0 上限 **32/s**，T7 上限 **256/s**。
- **超速率（overspeed）**：带子的推进速率是 `beltSpeed × itemSpacing = 1.26 格/s`（间距 0.63 格 ⇒ 净吞吐 2 个/s）；而 `ItemEjectorSystem._update` 里 `progress += 2 × Δt × beltSpeed × itemSpacing`，即**机器出口每 1/2.52 秒就能把 1 个物品推进一整格**——单口 **2.52 个/s = 1.26 × 带速**。所以：**出口直接贴 hub 槽（中间不隔带子）时，这一段的带宽上限比普通带子高 26%**；把多条带在贴 hub 处合流，就能吃满这 26%。16 槽 × 2.52 ≈ **40.3/s ≈ 20 条带当量**。
  - 这正好对上中文指南《超速率输送》里「中心 20 条满带输入」的实测。`[官方源码]` 推导 + `[社区教程]` 实测吻合。
  - 前提：合流器出口**不经过带子**直接接 hub 槽；中间隔一格带子就退回 2m/s。
- 但**不要把多条线并成一条再进 hub**：4 条 2/s 的线并成 1 条 → 只剩 2/s，等于砍掉 75%。正确做法是每条线各占一个槽。

## 3. 布局范式：专用线 vs MAM

### 3.1 专用线（Dedicated Line）—— 1~19 关的唯一正解

**结构**：一种形状一条独立产线，从矿点直通 hub 的一个独立槽。

```
矿簇(~20格)                                        hub
┌──────────┐   ┌───────┐   ┌───────┐   ┌───────┐  ┌────┐
│ miner×N  │──▶│ 上色  │──▶│ 切割  │──▶│ 堆叠  │─▶│槽  │
│ 0.4/s/台 │   │ ×6/带 │   │ ×4/带 │   │ ×8/带 │  │ #1 │
└──────────┘   └───────┘   └───┬───┘   └───────┘  └────┘
     ▲ 矿簇上能站的格子全部铺满          │
     │  （链式矿机只省带子，不加速度）    └─ 半切后有 2 个出口：
     │                                    要么两路各自往下走（= 2 条带），
     │                                    要么用一个出口、另一个接垃圾站
     └─ 5 台 = 1 条满带（同档）

第二种形状（独立一条线，独立一个 hub 槽）：
┌──────────┐   ┌───────┐                        ┌────┐
│ miner×N  │──▶│  ...  │───────────────────────▶│槽  │
└──────────┘   └───────┘                        │ #2 │
                                                └────┘
  ↑ 每条线独立，不共享带子、不在 hub 前合流
```

> 图中「上色在切割之前」是推荐顺序（官方 tip「Color your shapes before cutting for maximum efficiency」）；若目标形状只需要局部上色，才用四色上色器/分段上色。

要点：
- **每条线的每一段都按 §2.2 配平**；任何一段少于配比，整条线按最慢段跑。
- **串联优先于并联**（官方 tip「Serial execution is more efficient than parallel」）：机器出口直接怼下一台机器入口，省带子也省空间；只有需要「1 变 N」时才用分流。
- 产线建在**轴线路（axis lane）**旁边，输出直接上轴线回 hub（见 §5）。
- 旧线不拆：升级商店会反复要同一种形状（见 §4）。

### 3.2 MAM（Make Anything Machine）—— 20 关以后 / freeplay

**核心思想**：不预先造形状，而是把「hub 当前需要的形状」当作**信号**，实时驱动分拣、上色、切割、堆叠。

```
                  ┌──────────────────────────────────────────┐
 hub 需求信号 ───▶│ 信号分析：按层拆分 → 四切 → analyzer      │
 (hub 自带 wire   │ 得到 每层/每角 的 (形状, 颜色) 需求        │
  输出当前目标)   └───────────────┬──────────────────────────┘
                                  │ 比较器 + 过滤器（每角一套）
        ┌─────────────────────────┼─────────────────────────┐
        ▼                         ▼                         ▼
 ┌────────────┐           ┌────────────┐            ┌────────────┐
 │ 原料模块    │           │ 上色模块    │            │ 切割/重组   │
 │ 4 种基础形  │──────────▶│ 7 色 + 无色 │───────────▶│ 四切→旋转   │
 │ ×16 路供料  │           │ (按信号开阀)│            │ →按角归位   │
 └────────────┘           └────────────┘            └─────┬──────┘
                                                           ▼
                                          ┌──────────────────────────┐
                                          │ 堆叠模块 ×15（4 层 × 4 角）│
                                          │ 缺角时旁路，不堆叠         │
                                          └────────────┬─────────────┘
                                                       ▼
                                          ┌──────────────────────────┐
                                          │ 出货过滤 + 仓库缓冲(5000)  │
                                          │ 错形状→垃圾；满仓→burst    │
                                          └────────────┬─────────────┘
                                                       ▼  hub（多路并联）
```

**MAM 的三种实现档位**（按解锁时间线，`[官方源码]` levels.js）：

| 档位 | 解锁 | 能做什么 | 局限 |
|---|---|---|---|
| 半自动 | L20（wires）+ L21（filter） | 手动设一个形状，机器自动量产 | 换形状要人工改线 |
| 全自动 | **L25（virtual processing：analyzer / compare / 虚拟四件套）** | 读 hub 信号，自动换形状 | 换形要 flush，几分钟 |
| 完整 MAM | L25 + 仓库/蓝图 | 连续供多种形状、burst 交付 | 体量大、吃性能 |

**MAM 的真实代价**（中文建造实录 + 英文 Universal Factory 都提到）：
- 供料侧若「预造 128 种有色角块」会爆炸到 512 条带，游戏直接卡死/崩存档 → 必须**按需现造**，把物料模块缩到 1/8。
- 换形状时有 **flush 期**：旧形状卡在管道/机器/堆叠器里，必须用定时器开垃圾阀清空，否则堵死。实测「切换 5 分钟内」算优秀。
- 输出一般 1~4 条带；靠仓库 5000 缓冲做 burst 交付。

### 3.3 什么时候用哪个（决策表）

| 阶段 | 主力 | 理由 |
|---|---|---|
| L1–L11 | 专用线，1 形状 1 线 | 没有蓝图、没有 balancer 变体，模块化不划算 |
| L12–L19 | 专用线 + 蓝图模块（T1/T2 各一套） | 蓝图解锁，可复制；升级线开始要多种形状 |
| L20–L24 | 专用线为主；可玩半自动 MAM | wires 刚解锁，做全自动缺 analyzer |
| L25–L26 | 专用线保通关；MAM 可选 | 全自动 MAM 成本 > 收益，除非冲成就 |
| freeplay / L100+ | **MAM + 专用线混合** | 形状随机、种类无限，专用线不可能穷举 |
| 冲「MAM 成就」 | **在 27 级里建好 MAM，再交掉第 27 关** | 成就条件 `level > 27 && !failedMam`。`failedMam` 的监听器只在「交掉第 27 关」那一刻挂上，之后任何实体新增/销毁都会置真 ⇒ 27 级随便建，**交关后一格都不能动** |

> 结论：**「专用线 vs MAM」不是风格之争，是时间线问题。** 在 L25 之前硬做 MAM，等于用 19 关的资源造一台 25 关才需要、且缺零件的机器。

### 3.4 模块化与蓝图（高手和中级玩家的分水岭）

- 官方 tip 连发三条：「Make sure your factories are modular」「Invest time to build repeatable designs」「With modules, space is merely a perception」。
- 蓝图粘贴**不是免费的**，消耗「蓝图形状」（L12 的 `CbCbCbRb:CwCwCwCw`），成本约与实体数同量级 → 模块要**又小又常用**，不要复制一大坨一次性结构。
- 社区常用模块尺寸（`[社区教程]`，非源码）：切割/堆叠/混色 4×6，上色 4×5，四色上色 5×8。尺寸不是硬规范，**配比才是**。
- 建议维护一个「模块库空地」：远离 hub 的一块区域只放标准模块，需要时飞过去复制（中文新手攻略、英文 New Player Advice 都这么做）。

## 4. 升级与「徽章」策略

### 4.1 先澄清：shapez 1 **没有徽章系统**

- 1.5.6 的「升级」是右上角 shop 里的 **4 条线 × 若干 Tier**（Tier I…），每条线买一档，倍率 +improvement。
- 游戏内没有 badge / 成就徽章影响产能；成就（45 个）只是 Steam 成就，与工厂数值无关。
- 你说的「徽章/升级商店」大概率指 **shop 的 Tier 等级**，或者把 **shapez 2 的研究树/里程碑** 记混了。shapez 2 有独立的研究树与里程碑，但那是另一套系统（见 §6）。
- 证据：`[官方源码]` `regular.js` `generateUpgrades()` 只有 `belt / miner / processors / painting` 四条；`[官方文案]` `base-en.yaml` 的 `shop:` 段只有 `tier: Tier <x>`，全文件没有 badge 相关词条（唯一 `badge` 出现在 Puzzle DLC 编辑器说明里）。

### 4.2 四条线的真实成本（含「累计」机制）

`generateUpgrades` 里有个容易忽略的机制：**后面的档位会把前面所有档位的需求再要一遍，且每次 ×2.5 后再取整**（`tierGrowth = 2.5`）。所以 T3 不是「只要 1000 个」，而是「前面两档的所有形状 + 本档新形状」。

| 线 | T1 | T2 | T3 | T4 | T5 | 累计到 T3 | 累计到 T4 | 累计到 T5 |
|---|---|---|---|---|---|---|---|---|
| belt | 无色圆 ×30 | 无色圆 ×75 + 无色半圆 ×500 | + 紫圆 ×1000（本档 2,380） | + 红星 / 黄圆 ×6000（本档 11,940） | + 红星 / 黄圆 / 白星 ×25000（本档 54,100） | **2,985** | 14,925 | 69,025 |
| miner | 无色矩 ×300 | 无色矩 ×740 + 无色半圆 ×800 | + 青星 ×3500（本档 7,300） | + 白圆 / 蓝风车 ×23000（本档 40,500） | + 5 层复合 ×50000（本档 143,000） | **9,140** | 49,640 | 192,640 |
| processors | 无色星 ×500 | 无色星 ×1200 + 无色半矩 ×600 | + 绿圆青星 ×3500（本档 8,000） | + 白圆红圆 / 绿星 ×25000（本档 43,500） | + 3 层复合 ×50000（本档 155,000） | **10,300** | 53,800 | 208,800 |
| painting | **蓝半矩 ×600** | 蓝半矩 ×1500 + 红风车 ×3800 | + 紫矩 / 白圆 ×6500（本档 19,000） | + 紫风车 / 白圆 / 紫风车 ×25000（本档 69,000） | + 4 层复合 ×50000（本档 220,000） | **24,900** | 93,900 | 313,900 |

> 数字是我按 `regular.js` 的算法（`fixedImprovements`、`tierGrowth=2.5`、`findNiceIntegerValue`、`excludePrevious`）逐档复算的，`[官方源码]`。
> 读法：「本档 N」是该档**一次**要交的总量；「累计到 Tn」才是从 T0 一路买到该档一共要交多少。
> 形状码规则：**每个象限两个字母 = 形状 + 颜色**，四组顺时针，`--` 表示该象限为空，`:` 分层（左→右 = 下→上）。
> 形状：C=圆 R=矩 S=星 W=风车；颜色：u=无色 r=红 g=绿 b=蓝 c=青 p=紫 y=黄 w=白。
> 象限顺序是 **右上(0) → 右下(1) → 左下(2) → 左上(3)**。所以 `RbRb----` = 右半的**蓝矩形**（切割机切一半的产物）；`--CuCu--` = 左半的无色圆。

**关键对比**：26 关主线总共只要 **289,638** 个形状；而把四条线都买到 T4 就要 **212,265**（= 主线的 73%），买到 T5 要 **784,365**（= 主线的 2.7 倍）。**「升级买到 T5」比「打通主线」还贵**，这就是为什么高手说「升级要和关卡同步，不能只刷一样」。

### 4.3 该优先买什么：升瓶颈，不升「商店第一行」

| 情形 | 该买 | 理由 |
|---|---|---|
| 矿机数量已铺满矿簇，带子没满 | **miner** | 0.4→0.6 直接 +50% 矿石，全厂受益 |
| 矿机够、带子满载（吞吐 = 2/s） | **belt** | 只有带子成为瓶颈时，提速才转化为产量 |
| 切割/堆叠段堵、前段空转 | **processors** | 加工段是瓶颈 |
| 染料/上色段堵，或要省染料 | **painting** | 上色器 6 台/带是硬配比；双联上色器能减半染料 |
| 想尽早用蓝图 | 先买 **belt T1**（只要 30 个圆） | 几乎白送，但不加产，只降延迟/提上限 |

**最有价值的三个早期升级**（性价比，`[官方源码]` 成本 + `[社区教程]` 共识）：
1. **belt T1：30 个圆** —— 一杯咖啡的成本，先买不亏。
2. **miner T1：300 个矩形** —— 第一个真正加产的升级；L3 之后矩形线本来就要跑。
3. **processors T1：500 个星** —— 星在 (85,-23)，要专门拉一条线，但切割/堆叠全线 +50%。

**最不划算的早期升级**：painting T1 要 600 个「蓝半矩」（`RbRb----`）。看似简单（切一半的蓝矩形），但蓝色染料必须去 **>2 chunk** 的地方采，光是把蓝染料拉回来就是一条独立管线；而它只提升上色段速度。除非你已经在做染色形状（L6 之后必然要做），否则可以排最后。

### 4.4 「用一条万能产线喂所有升级」成立吗？

**结论：不成立，至少不能替代专用线。**

- 升级商店同时需要 4 条线、每档 1~5 种形状；一条 MAM 输出 1 条带（2m/s），**串行**生产：先产 A 再产 B，切换要 flush（几分钟）。
- 四条专用线是 **并行** 的：4 × 2m = 8m 个/s，同时产出 4 种不同形状。
- 而且升级扣的是 `storedShapes`，与关卡进度**共用同一个库存**（`[官方源码]` `tryUnlockUpgrade` 里 `this.storedShapes[o.shape] -= o.amount`；关卡进度读同一个 map）。一条 MAM 频繁换形状，会把库存搅成「每种都差一点」，反而更难凑齐。
- **成立的用法**：MAM + 大仓库（5000/仓）做 **burst 交付**——先攒满一种形状，再一次性倒进 hub。中文 MAM 实录的「交付模块」就是干这个的：一路缓存打满两条带，8 路并联冲 hub。`[社区教程]`

**推荐配置（L25 以后）**：
```
4 条专用线（圆/矩/星/蓝半）── 常驻，喂升级商店
        +
1 台 MAM ── 只在 freeplay / 新形状 / 成就时开机
```

### 5.2 硬规则（有出处）

1. **hub 周围 16 格内不放工厂**。官方 tip 两次警告「Don't build too close to the hub, or it will be a mess」「Building too close to the hub can get in the way of later projects」；社区 New Player Advice 给出具体数字：**16 格缓冲**，并解释「你以后会想在这里放分流/汇流装置」。`[官方文案]` + `[社区教程]`
2. **四条轴线（x∈[-2,2]、y∈[-2,2] 这 5 格宽的两条十字带）留给主干带**，每个方向铺 4 条，一直延伸到需要的地方。工厂贴着轴线建，输出就近上轴线。社区原话：「重要的是工厂离**轴线**多近，而不是离 hub 多近——带子上的运输时间不影响产量，全是流水线、单向、无往返延迟」。`[社区教程]`
3. **长距离并行带一次不超过 4 条，旁边留 2 格空隙**。因为 T1 隧道只能跨 4 格；超过 4 条并行，以后想横穿就得整组进隧道，非常难受。`[社区教程]` + `[官方源码]` `undergroundBeltMaxTilesByTier: [5,9]`（实际可跨 5/9 格，含出入口）
4. **矿点就近用，但工厂主体在缓冲区外**。开局红染料 (7,7)、圆 (-9,7) 都贴着 hub，允许「矿机在缓冲区内、带子穿出去」，但不要把加工厂盖在缓冲区内。
5. **给未来留整块矩形空地，而不是碎片**。无限地图不缺地，缺的是「连续 30×30 的空地」；碎片化之后想放 MAM 只能拆。

### 5.3 分区建议（按距离）

| 距离（chunk） | 资源特征 | 建议用途 |
|---|---|---|
| 0–2 | 固定矿 + 红/绿染料；形状簇 size 2、单形状 | 开局专用线、hub 缓冲、模块库 |
| 3–7 | size 2~3；仍无星/风车（<7） | 主升级线（圆/矩/星专线）、染料混色 |
| 7–15 | size 3；**风车开始出现**；四角开始随机 | 风车线、蓝色染料、复杂形状专用线 |
| 16–31 | size 3~4；四角随机 | 中期扩建、第二条 MAM 供料 |
| 32+ | size 5（~117 格/簇） | 大型矿区、freeplay 主基地 |

> 注意：**矿点不会枯竭**（地图下层是静态生成，没有 depletion 机制），所以「占矿」不是策略，「把矿铺满」才是。`[官方源码]`（`getLowerLayerContentXY` 只读地图，无储量字段）

### 5.4 要不要给未来留空？

要，但不是「留白越多越好」，而是**留三种特定形状的空**：

- **hub 四周 16 格环**：留给 16 路进料 + 超速率合流。
- **每条轴线两侧 2 格**：留给以后加车道/隧道。
- **一块 40×40 的完整空地**：留给 MAM（16 个物料模块 + 15 个堆叠模块 + 交付模块，实测占地远超想象）。

## 6. shapez 2 有什么不同（对照，不混用数字）

> 版本：**1.0，2026-04-23 发售**（Steam AppID 2162800，`[官方文案]` Store API / 商店页）。下面的数字全部是 shapez 2 的，**不要套到 1.5.6 上**。

### 6.1 机制层面的三个结构性变化

| 维度 | shapez 1.5.6 | shapez 2 (1.0) |
|---|---|---|
| 空间 | 单层平面，无限 2D 地图 | **3 层**（建筑层 + 平台层 + 层间连接），平台是 1×1/1×2 的「机器单元」 |
| 物流 | 传送带 + 隧道（跨 5/9 格） | 平台端口 + **space belt（12 lanes/720/min）** + **space train** + 液体管道 |
| 矿 | 固定矿点，直接铺矿机 | **小行星**，矿机平台（16 台矿机/平台）→ 4 条满载输出 |
| 配方 | 4 形状 + 7 色 | 形状 + 颜色 + **pin（针脚）+ crystal（晶化）**，且支持「operator 形状」随机生成 |
| 终点 | 26 关主线后 freeplay | 研究树 + 里程碑；后期是「无限随机 operator 形状」 |

### 6.2 shapez 2 的关键速率（1.0，`[社区教程]` 两份独立指南互证）

| 项目 | 早期 | 满级 | 换算到「1 条满级小带」（180/min） |
|---|---|---|---|
| 小带（platform belt） | 120/min | **180/min** | — |
| 矿机（extractor） | 30/min | **45/min** | **4 台 = 1 条带** |
| 切割机 | 30/min | **45/min** | **4 台/带** |
| 旋转机 | 60/min | **90/min** | 2 台/带 |
| 堆叠机（普通） | 20/min | **30/min** | **6 台/带** |
| 堆叠机（bent） | — | **45/min** | 4 台/带（更省） |
| space belt | — | **720/min × 12 lane** | 1 lane = 4 条满级小带；整条 = 48 条小带 |

> 两份指南分别给了早期/满级的数（30 vs 45、120 vs 180），但**比例恒定**：矿机 4 台、切割机 4 台、旋转机 2 台、堆叠机 6 台，对应 1 条满带。这与 shapez 1 的「所有升级一起缩放、比例恒定」是同一个设计哲学，1.0 之后官方干脆把「升级不再改变配比」写进了更新（Prime Platforms 评论区 + Modularization 指南）。`[社区教程]`

### 6.3 shapez 2 是否解决了 1.x 的布局痛点？

**解决了三个，没解决两个。**

解决：
1. **「平面空间不够」** → 3 层 + 平台化，同样面积能塞 3 倍机器；社区公认「平台不是额外地板，是机器单元」。
2. **「宽总线占地方」** → space belt 一条顶 12 条，长距离不再需要「编织带/7 宽/11×11 交叉」这类 1.x 的硬核布线技巧。
3. **「换形状要 flush 很久」** → MAM 用平台级模块 + 内建垃圾/旁路，换形时间从「几十分钟」压到「几分钟」（CROS-MAM v5 自称 5 分钟内）。

没解决（甚至更糟）：
1. **MAM 的复杂度爆炸**：pin/crystal/同层异色等限制让「真正万能」仍不存在，社区明确区分 **MAM** 与 **TMAM（真·万能，待研究）**。`[社区教程]`
2. **前期学习曲线**：3 层 + 液体 + 平台端口，对新手比 1.x 陡得多；多份指南都在教「怎么把平台当单元用」，说明这层抽象不自明。

### 6.4 对我们的直接含义

- 我们连的是 **1.5.6**，**不要**把 shapez 2 的 120/180/min、45/min、720/min 写进任何配比表。
- 但 shapez 2 的两条设计思想可以直接借：
  1. **「平台 = 有明确输入/输出/吞吐的机器单元」**——正好对应我们缺的「模块」概念；AI 应该先产出「模块库」，再用模块拼工厂，而不是每次从零摆格子。
  2. **「先配平，再扩展」**——一个配平过的单元，扩产就是复制它，不用重算。这条在 1.x 同样成立（同档倍率下配比恒定）。

## 7. 外行设计的特征清单（自检用）

按「一眼就能看出没入门」排序：

| # | 特征 | 为什么外行 | 后果 | 怎么检测 |
|---|---|---|---|---|
| 1 | 一个矿簇只放 1~2 台矿机 | 不知道矿机 0.4/s、带 2/s | 产能锁死在 1/5~1/10 | 数「矿机数 / 矿簇格数」< 0.8 |
| 2 | 工厂贴着 hub 盖 | 没读过官方 tip | 后期 16 路进料没地方，拆厂 | 检查 hub 16 格内实体数 |
| 3 | 多条线在 hub 前并成一条 | 以为「合流更整齐」 | 4 条带 → 1 条，吞吐砍 75% | 数 hub 槽占用 < 线数 |
| 4 | 切割机只用一个出口、另一个空着 | 不知道机器只有 2 个 charge 队列 | 切 2 个就停，整线卡死 | 找「输出端无 acceptor/垃圾」的切割机 |
| 5 | 死路带子（末尾什么都不接） | 不知道带子会一直囤货 | 上游全部堵死 | 找 `boundAcceptor == null` 的带子 |
| 6 | 先切后染 | 不知道上色器染整个形状 | 半切 → 形状 ×2，上色器需求 ×2；四切 → ×4 | 统计 painter 数 / 带 |
| 7 | 追求「精确均分」的 balancer 塔 | 把 Factorio 思维带进来 | 浪费空间，且官方明说不需要 | 找 8 台以上 balancer 串联 |
| 8 | 只升带子不升矿机 | 不知道加法倍率 | 配比 5 → 7.5，白丢 33% | 比较 upgradeLevels.belt 与 .miner |
| 9 | 拆掉旧产线 | 不知道升级要累计形状 | 升级进度归零/重建 | 检查历史实体删除记录 |
| 10 | 只生产当前关卡形状 | 不知道升级商店要别的形状 | 升级永远买不起 | 对比 4 条线的 required 与在产形状 |
| 11 | 没有仓库/缓冲 | 不知道 burst 交付 | 换形状时 hub 断供 | 找 storage 数量 = 0 |
| 12 | 在 L20 前硬造 MAM | 不知道 wires/analyzer 的解锁关 | 造不出来，或造出来不能自动换形 | 检查 level < 20 且有大量 wiring |
| 13 | 一条线从矿点直线拉 200 格到 hub | 不知道轴线/隧道 | 后期无法加线，横穿全乱 | 带子长度 > 100 且无隧道 |
| 14 | 堆叠机只放 1~2 台 | 不知道 0.25/s 是最慢机器 | 堆叠段成为全厂瓶颈 | 堆叠机数 / 带 < 8 |
| 15 | 用「关卡过了」当验收 | 不知道吞吐才是指标 | 后续关卡全部超时 | 只看 level，不看 delivered/s |

> 特别说明「腐坏率」：**shapez 1 没有任何腐坏/保质期/衰减机制**（1.5.6 的系统列表里没有相关系统，官方也未提及）。真正的「腐坏」是 **换形状后残留在管道/机器/仓库里的旧形状**——它会堵死 MAM，必须用定时垃圾阀 flush。`[官方源码]` + `[社区教程]`

## 8. 对 AI agent 的强制规则（5~8 条）

> 每条都对应一个我们真实犯过的错。建议直接写进 agent 的 system prompt / 校验器，违反即拒绝执行。

### R1. 产能必须从带速反推，禁止「一台机器就报喜」

- **规则**：任何产线提交前，必须计算 `N = ceil(该段带速 / 该机器速度)`，并断言每段实际机器数 ≥ N（矿机按矿簇格数铺满，不按「够用」）。
- **理由**：矿机 0.4/s vs 带 2/s，1 台 = 1/5 产能；矿簇 20 格只放 1 台 = 1/20。
- **违反后果**：关卡能过但耗时 5~20 倍；后续关卡直接超时；用户看到的是一座「假工厂」。
- **验收**：`production` 返回的 delivered 速率 ≥ 理论值的 80%，否则不算完成。

### R2. 禁止在 hub 16 格内建厂；每个 hub 槽独立进料

- **规则**：hub 周围 16 格缓冲区内只允许矿机、带子、隧道；每条产线必须独占一个 hub 槽，**禁止在 hub 前合流**。
- **理由**：官方 tip 两次警告；hub 有 16 个槽，合流会把 N 条带压成 1 条。
- **违反后果**：后期无地可放 16 路进料，吞吐被永久锁死；返工要拆整个厂区。

### R3. 任何机器输出必须有 sink（垃圾站/下游/仓库）

- **规则**：放置切割机、堆叠机、上色器、分流器后，检查每个 ejector slot 的 `cachedTargetEntity` 非空；为空则补垃圾站或下游。
- **理由**：机器只有 2 个 charge 的内部队列，输出堵 → 停摆；切割机天然有 2 个出口，只用 1 个必堵。
- **违反后果**：整条线在几秒内堵死，产量归零，而 `obs` 里看不出「堵了」，只会看到库存不涨。

### R4. 升级必须「同档 + 升瓶颈」，且不得挪用当前关卡目标形状

- **规则**：
  1. 四条线等级差 ≤ 1；
  2. 买之前先测哪一段是瓶颈，只升瓶颈段；
  3. 若 `upgrade.required` 里包含 `currentGoal.shape`，只有在 `storedShapes[shape] > required + 当前关卡需求量` 时才允许买。
- **理由**：倍率是加法，同档配比才稳定（5:1）；买升级会从 `storedShapes` 扣材料，而关卡进度读同一个库存，可能让关卡进度倒退。
- **违反后果**：配比从 5 变 7.5（白丢 33%）；或者刚过的关卡进度回退，出现「越升级越慢」。

### R5. 画在切之前；禁止先切后染

- **规则**：产线图中，painter 必须位于 cutter 的上游（除非该形状只需要局部上色，且已证明上色器数量足够）。
- **理由**：上色器染的是整个形状的所有象限（`cloneAndPaintWith` 遍历所有 layer/quadrant）；切开后 item 数 ×2（半切）或 ×4（四切），上色器需求同比例放大。
- **违反后果**：上色器数量与染料消耗成倍放大，全厂最容易堵的一段就是上色段。

### R6. L20 之前禁止尝试 MAM；L25 之前禁止承诺「全自动」

- **规则**：`level < 20` 时布局必须是专用线；`20 ≤ level < 25` 只允许半自动（固定信号 + filter）；`level ≥ 25` 才允许 analyzer 驱动的全自动 MAM。
- **理由**：wires L20、filter L21、analyzer/虚拟处理器 L25；之前做 MAM 缺零件，只能做成「手动改线」的假 MAM。
- **违反后果**：大量实体和蓝图币打水漂；MAM 换形状要人工介入，AI 却报告「已自动化」。

### R7. 禁止拆除仍在升级供应链上的旧产线

- **规则**：删除任何产线前，检查它生产的形状是否出现在**任何未购买**的 upgrade tier 的 `required` 里；如果是，拒绝删除，只能改建/扩产。
- **理由**：升级 T1~T5 会反复要同一种形状（例如圆从 30 一路要到 1100），拆了就重建。
- **违反后果**：升级进度停滞，玩家被迫重建；历史存档里表现为「工厂越玩越小」。

### R8. 报告必须给「吞吐 / 配比 / 占用」，不能只给「关卡通过」

- **规则**：每次任务结束的输出必须包含：每条线的实测 delivered/s、瓶颈段、矿机/矿簇覆盖率、4 条升级线等级、hub 槽占用数。缺一项视为未完成。
- **理由**：用户批评的正是「把过一关当目标」；过一关只需要 1 条 2/s 线，而 26 关需要 4 条以上并行 + 升级。
- **违反后果**：AI 持续在「能过但很慢」的局部最优里打转，永远建不出高手的工厂（我们 12 个实体 vs 玩家 3093 个实体的差距就是这么来的）。

### 附：可直接落地的验收伪代码

```text
# 倍率是加法：mult[tier] = 1 + sum(improvement[0..tier-1])
MULT = [1.00, 1.50, 2.00, 3.00, 4.00, 6.00, 7.00, 8.00]   # T0..T7

for each line in factory:
    B = 2 * MULT[line.beltTier]              # 该线带速
    for each stage in line.stages:
        speed = baseSpeed[stage.kind] * MULT[line.tierOf(stage.kind)]
        need  = ceil(B / speed)
        assert stage.count >= need            # R1
    assert hub.slotsUsed >= line.count        # R2（不许合流）
    assert all(ej.target != null for ej in line.ejectors)   # R3
    assert max(tier) - min(tier) <= 1         # R4（同档）
    assert painterBeforeCutter(line)          # R5
    assert minerCount >= patchTiles * 0.8     # R1（矿簇铺满）
assert measuredDelivered / B >= 0.8           # R8（实测 ≥ 80%）
```

## 附：三条最容易被忽略、但最值钱的结论

1. **「5 矿机 : 1 带」在任意升级档都成立**，因为矿机和带子按同一个加法倍率缩放；但**只升带不升矿会变成 7.5 : 1**。这一条同时解释了「为什么要同档」和「为什么 145 台矿机是正常数量」。
2. **hub 有 16 个槽，且「贴着 hub 喷」比「经带子进 hub」快 26%**（ejector 推进 = 1.26 × 带速）。16 槽 × 1.26 ≈ 20 条带，这就是社区「20 带冲 hub」的源码解释。
3. **MAM 不是「高级布局」，是「L25 之后才存在的布局」**。在 L25 之前，专用线 + 蓝图模块 + 同档升级，才是高手和新手真正的分界线。

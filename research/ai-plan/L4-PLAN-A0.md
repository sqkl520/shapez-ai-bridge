# L4 方案 A0：插入现有向上段（最小改动）

日期：2026-10-27
来源：`L4-COMPILER-DIAGNOSIS.md` §6.4 提出，主线程逐格核实

## 一句话

在现有钌线的向上段 `(4..5, -13)` 处插一台切割机，只需 **+2 实体**（切割机 + 垃圾桶），
靠现有的 4 台矿机产能，约 **44 秒**产出 70 个 `RuRu----`。

## 为什么这条线插得进去

`WHY-NO-CUTTER-INSERT.md` 说"插不进去"，只对了一半：

- 它试的是 `x=1` 那条 **r=180（向下）** 的主干 —— 方向确实不匹配
- 但 `x=2..5` 从 `y=-9` 到 `y=-15/-20` 是 **r=0（向上）** 的
- 切割机 `r=0` 的输入恒在 `(x, y+1)`（南侧），输出在 `(x, y-1)` / `(x+1, y-1)`（北侧）
- **向上流的产线天然满足这个方向**

## 切割机槽位（实测确认）

`op-templates.mjs:266-276`：
```
inputs:  [slot([0,0], "bottom")]        ← (4,-12) 的货，向上喂入
outputs: [slot([0,0], "top", "left"),   ← (4,-14) 废料 = ----RuRu
          slot([1,0], "top", "right")]  ← (5,-14) 目标 = RuRu----
```

`cutHalf` 验证（诊断 §6.3）：
```
h[1] (slot right → (x+1,y-1)) = [[rect,rect,null,null]]
goal (RuRu----)               = [[rect,rect,null,null]]
h[1] === goal ? true
```

**所以 `(5,-14)` 那条已有的带子正好接住目标半块，一格都不用加。**

## 代价：x=5 流路会停摆

切割机只有一个 acceptor，在左格 `(4,-13)` 的下方 `(4,-12)`。
`x=5` 的货推给 `(5,-12)` 时，上方 `(5,-13)` 现在是切割机右格，**不收** ⇒ 堵。

**影响**：4 台矿机里只有 `x=4` 那台在供料给切割机。
- 1 台矿机 0.4/s → 切一半 0.2/s → **70 个需 350 秒（约 6 分钟）**

这是可接受的。若要恢复 x=5，需要把 `(5,-12)` 的货引到别处（新铺通道），
但 `x=6` 全空、需要新铺 12+ 格，性价比不高。

## 回滚

- 删切割机 `(4,-13)`、trash `(4,-14)`
- 在原位补回 `(4,-13) (5,-13) (4,-14)` 三条 `belt r=0 code=1`
- uid 会变（新分配的），但拓扑完全复原

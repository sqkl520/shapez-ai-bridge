# M4（多分支汇合）：**部分达成** —— 附一份宝贵的"布局陷阱表"

> 诚实记录：M4（两分支 → 一个 stacker 的完整汇合）**未通过**。
> 但它失败的方式**极有价值**——它精确暴露了"手写布局"会在哪里出错，正是布局编译器要解决的问题。

## 到底发生了什么

两个分支**各自都完美工作**：
```
(135,100) CuCuSuSu ×3      ← 矿A 的原料
(136,96)  CuCu---- ×3      ← 切割后取右列 ✓
(136,93)  --CuCu-- ×3      ← 再经 rotater 旋转 ✓（CW 后右列变下排）

(147,100) RuRuCuCu ×3      ← 矿B 的原料
(148,96)  RuRu---- ×3      ← 切割 ✓
(148,93)  --RuRu-- ×3      ← 旋转 ✓
```

**两条分支的完整链（矿机→切割→旋转）都跑通了** —— 这部分是成功的。

但**物品停在 rotater 输出，没能到达 stacker**。诊断出的合并区布局：

```
  (141,90) belt r= 90 rv=1   ← 拐角（但 rv=1 = 左转，而我们需要它"先右后上"）
  (142,90) belt r=  0 rv=0   ← 竖直，但它在 (142,90)，而水平段来自 (137..141, 90)
  ...
  (142,92) belt r=270 rv=2   ← B 分支的拐角
  (142,91) belt r=  0 rv=0   ← 单格竖直
```

**根因（三条，都是手写布局的典型错误）**：

1. **对角缺口**：A 分支的竖直通道在 x=136，而水平车道在 y=90 —— 
   但水平段我写的是 `[colA-1, cornerAy] → [sx+1, cornerAy]` = `(135,90) → (142,90)`，
   而竖直段是 `(136, rotA-1) → (136, cornerAy+1)` = `(136,92) → (136,91)`。
   **`(136,90)` 这一格（拐角）由 `cornerA1` 放在 (colA=136, cornerAy=90)** —— 看起来对，
   但水平段从 `(135,90)` 开始，**多了一格 (135,90) 并且它朝右**，
   而 (136,91) 的竖直带朝上、`(136,90)` 是拐角 —— 于是 **(136,90) 收到了来自下方 (136,91) 的货，
   但它的 rotation rv=1 表示"左转"，会往左喷到 (135,90)**，而 (135,90) 朝右又会喷回 (136,90)……
   **形成死循环/死端**。

2. **`rv`（rotationVariant）是邻居派生的**（`belt.js:161`）：我在放拐角格时用了显式 `r=90`，
   但 `rv` 仍由游戏按邻居算 —— 结果算成了"左转"而不是我想要的"从下上来、向右去"。

3. **格数对不上**：我手算的行列偏移有 1~2 格的累积误差（B 分支"竖直1"说明它几乎没竖直段）。

## 为什么这个失败是宝贵的

它**精确证明**了 `SYNTHESIS.md` 的核心论断：

> **"把生产 DAG 摆成不交叉、不堵塞、能运转的工厂"没有任何现成方案**——
> 这才是真问题。

本次手写布局只涉及**两个分支 + 一个汇合点**（总共 50 个实体），我就犯了三类错。
真实工厂有 **2805 个实体**、几十个汇合点 —— **人工手写完全不可行，必须由编译器做**。

## 📋 布局陷阱表（布局编译器必须处理的坑，本次全部实际踩到）

| # | 陷阱 | 现象 | 编译器对策 |
|---|---|---|---|
| 1 | **传送带 rv 由邻居派生** | 显式指定 `r` 不够，`rotationVariant` 仍按邻居算，可能与意图相反（左转 vs 右转） | **不要手算 rv**：① **在所有邻居就位后再放拐角格**（最简单，M4-SUCCESS 用此法通过）；② 或生成蓝图（需先修 `placeOne` 的 rv 覆盖 —— 已修，见 `facts/RV-FIX-verified.md`） |
| 2 | **对角缺口** | 竖直段与水平段的行列对不齐，出现"拐角格缺失"或"多一格" | 布局必须是**网格作图的确定性算法**（先算行列，再逐格填），不能手写坐标 |
| 3 | **退化段**（from==to） | `place_path` 报 2001，整个脚本中断 | 路径生成器必须过滤零长度段（本次加了 `placeSeg` 包装） |
| 4 | **输出/输入方向冲突** | stacker 的两个输入都朝上、输出也朝上 → 输出带与输入带同列冲突 | 编译器要有"分层/绕行"的规则（M3 验证过"抬高一行"模式） |
| 5 | **两条车道必须不同行** | 两个分支的横向搬运若在同一行会交叉/冲突 | 车道分配要有序号（本次用 cornerAy/cornerBy 不同行，是对的） |
| 6 | **不能边想边放** | 顺序错了，先放的带子按当时的邻居定型，后来邻居变了但带子不会更新 | **先放机器 → 再放直线段 → 最后放拐角**（邻居齐全时） |
| 7 | **废弃输出必须接走** | cutter 的另一半不接 → 堵死整机（开发期 B3 的坑） | 编译器必须为每个**未被使用的输出槽**自动接 trash |

**这 7 条是本次研究的直接产出**，比"M4 通过"更有价值 ——
它们把"布局很难"这句空话，变成了**7 条可实现的工程需求**。

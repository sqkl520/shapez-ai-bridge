# 决定性实验：离线资源图的实机可用性（主 Agent 实测）

> 回答："离线算出的资源图，AI 能直接用吗？" 两个实验都通过。

## 实验 1（H1）：预测 → 生成 → 建矿机

`research/ai-player/exp-offline-map.mjs`

```

obs 已知资源格: 3002
区域 [200,100,260,160]: 离线 127 格，其中 obs 未知 127 格
实验目标格: (231,171) 预测形状 = SuRuRuSu
移动相机到 (231,171) ...
观测该区域: 43 格资源；目标格现在有资源？ true（形状 SuRuRuSu）
  预测 vs 实测: SuRuRuSu vs SuRuRuSu  → ✅ 一致
在 (231,171) 放矿机 ...
  ✅ 矿机放置成功 uid=21123
  （清理：已删除）
=== 结论 ===
H1 成立：离线预测的资源格在实机可用 → 「离线全知规划 → 实机执行」闭环可成立。
```

## 实验 3（H3）：真·盲建 —— 完全不观测（干净版）

`research/ai-player/exp-offline-map-3.mjs`

H2 有一个混淆因素：它在放置前做了 `obs`，而 `obs` 本身会触发生成。H3 排除这个因素 ——
**全程不 obs、不 camera，直接 place**。

```
目标: (-1518,1450) 预测 RuRuRuSu（距原点 2099 格，全新象限）
>>> 注意：以下不进行任何 obs/camera —— 直接放置 <<<
✅ 真·盲建成功 uid=21125（26ms）
事后观测: 资源=[[-1518,1450,"RuRuRuSu"]]  矿机=在
（清理：已删除）
=== H3 结论 ===
H3 成立：完全不观测也能在预测坐标建 —— AI 可直接在离线规划的位置施工，无需探索。
```

**关键数字**：**2099 格**外、**全新象限**、**零观测**、**26ms**、预测 `RuRuRuSu` **逐字节准确**。

## 实验 5（H5b）：★ **物品真的在流动**（决定性）★

`research/ai-player/exp-remote-belt-3.mjs`

H4 只证明了"能建"，没证明"能运"。H5b 用**离线存档解码**读出带上物品（`dump.beltPaths`，
用 `dump.entities` 把 `entityPath` 里的 uid 映射成坐标）：

```
矿机@(-958,2690) 预测 blue   距原点 2855 格（未生成区域）
带子 applied=24，快进 2000 tick，存档并离线解码：

[远端（未生成区域）] 路径数=1  有物品的=1  物品总数=20
   样例: path_len=24, items=20, item0 = color:blue    ← 预测 blue，带上就是 blue！
[对照（hub 附近）]   路径数=1  有物品的=0  物品总数=0

✅ H5b 成立：远端未生成区域的带子上有物品 → 物流功能完整。
```

**这是在 2855 格外的未生成区域，矿机真的产出了预测的物品（`blue`），并沿传送带流动了 24 格**——
预测类型与实物**逐字节一致**。

### 🆕 附带能力：存档解码 = "带内物品"的观测通道

`obs` 只列建筑，看不到带上物品。但 `save_now` + `recon/decode_full.cjs` 能读出
`dump.beltPaths[].items`（真实工厂里 **483 条路径带物品**）。
**这是一个现成的、无需改 mod 的"物流观测"方案** —— AI 可以用它诊断堵塞/流速。

这完全绕开了"逐个动作、边走边看"的低效循环——是本次研究最强的单项结论。

## ⚠️ 仍未验证 / 边界

- 长链**跨越极长距离**（>5000 格）或**超大规模**（数百格）时的性能与边界。
- 未生成区域的**复杂机器交互**（cutter/stacker/painter 的输入输出）是否完全正常
  （H5b 验证了 miner→belt；H6 建出了实体但未验证其生产功能）。
- 蓝图**粘贴后与外部物流的连接**（接口对齐）——见 `facts/blueprint-format.md`。
- 游戏窗口最小化/无渲染时的行为。

## 🆕 附带发现：`obs` 是一个"侦察/生成"原语

观测某个 `region` 会**触发该区域的 chunk 生成**（游戏按需生成 chunk）。这意味着：
- **AI 可以用 `obs` 当"侦察"用**：想知道某片区域长什么样 → `obs region` 一下，数据就来了。
- 这也意味着**离线预测的正确用法**：先离线算出"哪里有好资源"（快、免费、全局），
  再 `obs`/`camera` 那一片让它生成，然后建 —— **不需要真的"探索过去"**。
- 对未来的 `obs` 优化有含义：region 查询会有副作用（生成 chunk），文档里应说明。

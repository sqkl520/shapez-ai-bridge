# 2677 字符的教学，和 4221 次真实调用几乎不相干

2026-11-22。只读分析。

## 教学说什么

`## BUILD ORDER FOR A COMPOUND SHAPE`（135 字符标题 + 约 900 字符正文）要求：

```
1. raw supply    — 矿机挖矿，铺带子送到工作区
2. pigment cascade — mixer 自底向上混（blue+green 先，再 +red 得 white）
3. half-shapes   — cutter 切两半，留要的那半，另一半送 trash
4. painting      — painter 一台一种颜料
5. stacking      — stacker 叠成两层
```

外加 `## SHAPE CODE CHEAT SHEET`（1019 字符）和
`## THERE IS NO "BUILD THE WHOLE LINE" MACRO`（957 字符），
合计 **2677 字符**，占 user 的 19%。

它们只在**配方不可用**时出现 —— 而 L12 的配方是 `ok:false`（solver capped），
所以**每一轮都在**。

## 真实调用是什么

L12 全部 4221 次宏调用：

| 宏 | 次数 | 占比 | 属于教学的哪一步 |
|---|---|---|---|
| `connect` | 2501 | **59.3%** | 第 1 步的一部分（铺带子），但绝大多数是修既有线 |
| `replace_run` | 590 | 14.0% | —— 不在教学里 |
| `remove_run` | 502 | 11.9% | —— 不在教学里 |
| `trash_unused` | 397 | 9.4% | 第 3 步的附带 |
| **`insert_machine`** | **133** | **3.2%** | **第 1-5 步的核心动作** |
| `remove_machine` | 87 | 2.1% | —— 不在教学里 |
| `extend_line` | 11 | 0.3% | 第 1 步的一部分 |

**模型的 96.8% 的动作在动已有的线，只有 3.2% 在建新东西。**

而教学要求它「按这个顺序建整条链」。

## 这意味着什么

1. **教学不是「写了但没生效」，是「写错了对象」。**
   它假设模型会去建新链，而模型的注意力全在既有线上。
   `connect` 占 59% 本身就说明：它认为问题在「哪条线没接上」。

2. **这和 506 个快照的零进度是同一件事的两面。**
   零进度 → 模型看到的诊断全是「这条带子到不了 hub」「这台机器缺进料」
   → 它去修这些 → 修的是 L11 的遗留线 → 零进度。

3. **2677 字符换来的效果，可以从 census 估出来：约等于 0。**
   如果教学真的改变了行为，`insert_machine` 的占比不会是 3.2%。

## 但**不要**直接删

删掉会有一个直接后果：现在这 2677 字符占着预算 **19%**，
删了能换回大量带子名额和 CAPACITY 空间。

**但**它在「配方真的不可用、而模型确实需要建线」的场景下是对的 ——
比如 L4/L5 那种小目标。问题只在 L12：那里模型被既有世界的诊断带偏了。

所以更可能的正确做法不是删，是**让它有条件**：

- 当 `PROGRESS` 显示「本关目标 absent 且从未进过 hub」时，教学**该强化**
  （而不是削弱）—— 那正是「你需要真正建一条新链」的时刻
- 当已有大量可改造的线时，教学可以缩

这需要先知道 `PROGRESS` 那行上线后模型的行为有没有变
（真机验证正在跑）。在那之前不动它。

## 下一步该量的

如果 `PROGRESS` 生效（模型开始建 L12 的链），`insert_machine` 的占比应该上升。
**这是一个可测的、跨 run 的行为指标**，而且不需要真机 ——
只要读 `transcript.jsonl` 里的宏分布。

建议做成一个常驻的观察：每 N 个 run 统计一次宏分布，
`insert_machine` 占比是「模型在不在建东西」的直接读数。

# prompt 预算已经饱和

2026-11-21。

## 实测

L12 真机快照，`prompt_tokens_max = 5300`：

```
system 4725 + user 13897 = 18622
targetChars = 5300 × 3.5 = 18550
余量 = -72
```

**已经超了 72 字符。** `over_token_budget: true` 只是标记、不抛错，
硬上限 `in_chars_max: 24000` 还很远 —— 但 `targetChars` 是**带子截断的判据**。

## 这意味着什么

**任何新增信息都在和「多显示一条带子」竞争。**

今天试了三次，三次都被同一道闸挡住：

| 想加的东西 | 成本 | 结果 |
|---|---|---|
| `## HUB` 里「已接的入口不能再接」的说明 | ~66 字符 | `belts_shown` 16 → 15（收敛到 L4 夹具后 +70，接受了） |
| MACHINES 图例讲 `port=a|b` | 独立一行 ~60 字符 | **12 → 11，D1 打红** |
| 给 `to:Endpoint` 参数加说明 | ~30 字符 | **同样挤掉一条带子** |

最后那条规则压进**已有图例行**、逐字抠措辞（58 → 61，只 +3）才通过。

## 为什么不能抬预算

`prompt_tokens_max` 已经从 4600 抬到 5300（那天抬的理由是：4600 档要牺牲 6 条带子）。
再抬不是不行，但每抬一次就是在推迟「把东西塞进去」这个决定。

而带子的优先级是**结构性**的：它是模型**唯一能就地改造**的对象 ——
`prompt.mjs` 里那段「带子优先」为此写了三档降级链（机器表 20 → 12 → 6 → 0）。

**规则可以等一轮再从 hint 学到；带子看不见就什么都做不了。**

## 现在的规则

写进 prompt 的任何东西，都要先回答：

1. 它占多少字符？（渲染后，不是源码长度）
2. 它会挤掉几条带子？（跑 `prompt_capacity.test.mjs` 的 D1 和
   `tohub_machine.test.mjs` 的 E）
3. 它能不能并进**已有的**行？（图例、段头、参数说明）

## 尚未验证的出路

- **L1（system prompt）里还有空间吗？** 4725 字符，是 prompt cache 的前缀，
  改它会让缓存失效，但不参与 `targetChars` 的计算。值得单独评估。
- **诊断 hint 的预算**：8 条诊断占 2991 字符（平均 374/条）。如果某几条的
  hint 能合并，能腾出可观的空间。
- **`MACHINES` 段 20 台 × ~60 字符 = 1200。** 降级到 12 台能省 ~480 字符，
  但那会让模型看不见某些机器。
